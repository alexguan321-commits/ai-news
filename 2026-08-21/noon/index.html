0821-午报 | Claude Code被曝隐写标记用户请求：AI信任危机全面爆发

2026-08-21 14:00:00 +0800 ☀️ 午报 👁 - views

📌 今日最重要的一件事

Claude Code 被曝在系统提示中隐写标记用户身份——AI 行业的"水门事件"

今天最重要的不是某个模型又刷了榜，而是一个信号：AI 行业最核心的信任基础正在被侵蚀。

安全研究者 Thereallo 在审查 Claude Code（v2.1.196）的二进制文件时，发现了一个隐蔽的隐写标记系统（Steganographic Marker System）——Claude Code 会在每次发送给 API 的系统提示中，通过替换肉眼不可见的 Unicode 字符来标记用户的身份类别。

🔗 来源：Thereallo Blog

技术细节：它到底做了什么？

Claude Code 在系统提示中插入日期字符串 Today's date is 2026-06-30.，然后秘密替换其中两个字符：

1. 撇号替换：Today's 中的 '（标准 ASCII 0x27）被替换为三种不同的 Unicode 撇号之一 2. 日期分隔符替换：- 被替换为 /

这些替换不是随机的——它们编码了两个维度的信息：

用户类别 撇号字符 含义
普通用户（未知域名） ' (U+0027) 标准 ASCII
已知域名用户 ' (U+2019) 右单引号
实验室关键词用户 ʼ (U+02BC) 修饰符字母
已知 + 实验室用户 ʹ (U+02B9) 修饰符素数

关键发现：代码中还特别检测了 Asia/Shanghai 和 Asia/Urumqi 时区——这意味着中国用户被单独标记。

为什么这件事比看起来更严重

让我用第一性原理拆解这件事的深层含义：

第一层：这不是 bug，是 feature

代码逻辑清晰且有意设计： 


function edp(known, labKw) {
  if (!known && !labKw) return "'";        // 普通用户
  if (known && !labKw) return "\u2019";    // 企业用户
  if (!known && labKw) return "\u02BC";    // 研究机构
  return "\u02B9";                          // 企业+研究机构
}

这不是意外泄露，是刻意设计的遥测系统。

第二层：这违反了 AI 行业的隐性契约

用户给 Claude Code 文件系统、Shell、Git、浏览器的完整权限——这是极高的信任。作为交换，用户期望客户端二进制文件是"无聊的"（boring）——即只做声称要做的事情。

隐写标记系统打破了这个契约：

  • 用户不知道自己的请求被标记
  • 用户无法选择退出
  • 用户无法审计这些标记的用途

第三层：这创造了一个新的攻击面

如果 Anthropic 可以在系统提示中隐写标记用户，那么：

  • 其他 AI 公司也可以这样做（OpenAI、Google、Meta）
  • 恶意行为者可以利用类似技术进行提示注入攻击
  • 监管机构将获得新的干预理由

🎨 自由发挥

如果 AI 工具都是"诚实"的，世界会怎样？

想象一个世界，所有 AI 工具都是完全透明的：

  • 你知道 AI 工具收集了哪些数据
  • 你可以选择退出数据收集
  • 你可以审计 AI 工具的行为

在这个世界里：

  • 信任度提升：用户更信任 AI 工具，采用率更高
  • 竞争更公平：公司通过产品质量竞争，而不是隐藏行为
  • 创新更快：开源工具可以快速迭代，推动技术进步

但这也有代价：

  • 成本更高：透明需要额外的工程投入
  • 体验可能下降：某些数据收集确实有助于改进产品
  • 隐私悖论：用户说要隐私，但行为上却愿意用数据换便利
